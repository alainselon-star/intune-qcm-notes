Microsoft Intune — Modes de gestion

Fiche de synthèse du chapitre « Modes de gestion » (par plateforme)

Ce chapitre répond à une seule question : comment Intune prend-il le contrôle d'un appareil ou d'une application ? Il pose d'abord un socle conceptuel — MDM (gestion du périphérique) contre MAM (gestion de l'application) — puis décline ce socle sur trois plateformes : Windows, iOS/iPadOS/macOS et Android. Sur chaque plateforme revient le même axe de lecture : un mode léger pensé pour le BYOD (l'appareil reste personnel) face à un mode complet pensé pour un appareil d'entreprise (contrôle total, effacement à distance).

1.Concepts : MDM et MAM

MDM — Mobile Device Management Gère l'appareil

Contrôle centralisé de l'appareil entier : inscription (enrollment) dans Intune, application de stratégies de sécurité, configuration réseau, déploiement d'applications, suivi de conformité. Couvre tout le cycle de vie du périphérique, de l'enregistrement au retrait, avec verrouillage/effacement à distance en cas de perte ou de vol.

MAM / APP — Application Protection Policies Gère l'application

Sécurise et gère les applications professionnelles indépendamment de l'appareil sur lequel elles tournent — même un appareil non inscrit dans Intune peut voir ses applications pro protégées : code PIN, chiffrement des données, contrôle du copier-coller ou de la sauvegarde vers des emplacements non sécurisés. Application granulaire, politique par politique. Particulièrement adapté au BYOD.

MDM + MAM sont combinables Un appareil d'entreprise entièrement géré via MDM peut recevoir en plus des stratégies MAM sur des applications sensibles, comme couche de sécurité supplémentaire. Les entreprises peuvent aussi révoquer l'accès et effacer les données pro d'une application sans toucher aux données personnelles de l'utilisateur.

Le portail d'entreprise Intune (Company Portal) revient sur toutes les plateformes avec un rôle variable : point d'entrée pour l'inscription, relais technique vers Intune, ou simple interface libre-service pour l'utilisateur. La communication appareil ↔ Intune passe toujours par Internet via des API REST sécurisées, sans VPN nécessaire.

2.Modes de gestion Windows

Windows propose quatre modes MDM — traditionnel, moderne, cogestion, coexistence — plus un mode MAM via Microsoft Edge.

ModePrincipeOutils / protocole
TraditionnelCycle de vie classique : déploiement de l'OS, déploiement d'applications, gestion des mises à jour, conformité/paramétrage. Poste verrouillé sur un standard d'entreprise, pas d'usage personnel.Configuration Manager, Active Directory / GPO, WSUS, MDT
Moderne / cloud nativeCycle adapté à la mobilité : enregistrement → provisionnement des ressources → gestion/protection → retrait/effacement.OMA-DM (ou le nouveau WinDC) via Intune
Cogestion (co-management)Pont entre Configuration Manager et Intune pour migrer en douceur : chaque charge de travail peut être basculée individuellement vers Intune.Configuration Manager + Intune (couple unique proposant la cogestion)
CoexistenceUn MDM tiers (pas Intune en cogestion officielle) est détecté par le client ConfigMgr, qui se désactive automatiquement sur les fonctions concernées.ConfigMgr ne garde que l'inventaire, le contrôle d'usage logiciel et la gestion d'alimentation
Traditionnel→ Cogestion→ Moderne (100 % cloud)

C'est la trajectoire résumée par le schéma du livre : les trois modes ne sont pas des choix isolés mais des étapes d'une même progression vers une gestion entièrement native au cloud.

Cycle de vie du périphérique moderne

  1. Enregistrement du périphériqueDans la solution d'administration (Intune).
  2. Provisionnement des ressources d'entrepriseProfils, applications, accès configurés automatiquement.
  3. Gestion et protection du périphériqueStratégies de sécurité, conformité, mises à jour.
  4. Retrait / effacement des donnéesFin de vie ou perte/vol du périphérique.

Méthodes d'inscription Windows dans Intune

Windows Autopilot Recommandé · Corporate

Le périphérique est connu du service et suit un processus de provisionnement automatique guidé pour l'utilisateur.

Jointure manuelle à Microsoft Entra ID Recommandé · Corporate

Enregistrement automatique dans Intune lorsque l'utilisateur joint manuellement le périphérique au tenant.

Hybridation avec Active Directory (Entra Hybrid Join) Corporate

Enregistrement automatique via une stratégie de groupe, quand l'entreprise hybride ses machines avec Entra ID.

Cogestion avec Configuration Manager Corporate

Enregistrement automatique dans Intune quand la cogestion est activée dans Configuration Manager.

Package de provisionnement (Windows Configuration Designer) Non recommandé

Un package exécuté sur la machine réalise la jointure au tenant et l'enregistrement automatique dans Intune.

Enregistrement manuel par l'utilisateur, dans Intune uniquement BYOD · Non recommandé en corporate

Ne joint la machine à aucun domaine. Scénario pour périphériques personnels (BYOD) — la machine est identifiée comme « personal ».

Deux agents techniques distincts sur la machine gérée Client MDM (OMA-DM + CSP) — les Configuration Service Providers exposent des nœuds de configuration hiérarchiques, accessibles par URI, qui servent de pont entre les stratégies MDM et les réglages système sous-jacents. C'est le canal standard.

Intune Management Extension (IME / sidecar) — agent complémentaire qui étend la gestion au-delà des CSP : scripts PowerShell et applications Win32 (Windows ou macOS), pour tout ce que les CSP ne couvrent pas nativement.

Cas particulier : l'agent Microsoft Defender for Endpoint (MsSense) embarque un mini-agent MDM capable de récupérer des stratégies de sécurité auprès d'Intune — ce qui permet de gérer des éléments de sécurité sur des machines non inscriptibles dans Intune, comme des serveurs.

Cogestion : charges de travail basculables vers Intune

La cogestion débloque des fonctionnalités cloud (accès conditionnel avec conformité, actions à distance, visibilité centralisée, lien avec Entra ID, provisionnement Autopilot) et permet de basculer, charge de travail par charge de travail, l'autorité de gestion vers Intune :

  • Stratégies de conformité
  • Stratégie de mises à jour logicielles
  • Configuration du périphérique
  • Stratégies d'accès aux ressources de l'entreprise
  • Gestion de la sécurité du périphérique (suite Microsoft Defender : Antivirus, Firewall, Credential Guard…)
  • Gestion des applications Office Click-to-Run
  • Déploiements d'applications clientes

Par défaut, le client Configuration Manager garde le contrôle de tout. Une charge de travail basculée fait que les stratégies reçues côté ConfigMgr sont désactivées (non interprétées) au profit de celles reçues par l'agent MDM Intune. Le co-management n'a jamais été pensé comme une solution définitive : certaines entreprises (usine, contexte de sécurité spécifique) ne migreront jamais entièrement vers le cloud.

MAM via Microsoft Edge

Dernier mode évoqué pour Windows : le périphérique n'est pas inscrit dans Intune. C'est la création d'un profil Edge avec le compte utilisateur de l'entreprise qui permet au navigateur de récupérer des stratégies et de restreindre certaines actions (copier/coller…) sur les applications web pro, afin d'empêcher la fuite de données.

3.Modes de gestion iOS/iPadOS et macOS

Device Enrollment BYOD basique

Le mode historique. N'importe quel appareil Apple peut s'enregistrer dès lors que l'utilisateur installe le portail d'entreprise et utilise son compte pro. Sans préenregistrement par l'administrateur, l'appareil est identifié « personal ». S'applique à iOS, iPadOS et macOS.

User Enrollment BYOD confidentiel

Le plus récent, pensé pour la confidentialité en BYOD — équivalent du Work Profile Android. Un identifiant Apple géré (Managed Apple ID) est créé ; l'espace de travail y est associé. Pas de séparation visuelle des applications (contrairement à Android), mais les données sont chiffrées et le partage contrôlé. L'effacement pro n'affecte pas les données personnelles. Non disponible sur macOS.

Supervised Corporate · irréversible

Fonctionnalités avancées : Activation Lock (verrouille l'activation à l'organisation, anti-vol), restrictions poussées (caméra, Safari, AirDrop…), déploiement silencieux d'applications, localisation et effacement à distance. Ne peut être retiré sans réinitialisation complète — à réserver aux périphériques d'entreprise. Sur macOS, la supervision se limite à l'Activation Lock.

Trois façons d'obtenir le mode Supervised

MéthodeUsage
Apple ConfiguratorPréparation manuelle, appareil par appareil, via Mac ou iPhone récent. Peut aussi servir à enregistrer un appareil dans ABM/ASM s'il n'a pas été préenregistré par le revendeur (libération possible par l'utilisateur pendant 30 jours après l'inscription Intune).
Direct Enrollment (macOS uniquement)Inscription en masse sans accès à ABM/ASM, ou nécessitant une connexion réseau câblée. N'associe pas l'appareil à un utilisateur — réservé aux postes partagés / kiosques.
Automated Device Enrollment (ADE, ex-DEP)La méthode recommandée. Via Apple Business Manager (ABM) ou Apple School Manager (ASM) : l'appareil neuf se connecte et se configure automatiquement dès le premier allumage, avec un Setup Assistant personnalisable (masquage des étapes Apple ID, Siri…).

Architecture technique : protocole MDM Apple avec agent natif à l'OS, notifications via l'Apple Push Notification Service, authentification par certificat. Nouveau protocole déclaratif DDM (Declarative Device Management), équivalent du WinDC Windows : le client applique un état désiré et résout lui-même les conflits. Sur macOS, l'IME/Sidecar complète pour tout ce que les protocoles Apple ne savent pas gérer (scripts, installations d'applications).

4.Modes de gestion Android

Android Device Administrator (DA) Déprécié

Le tout premier mode (Android 2.2). Google retire progressivement ses API. Reste utilisé pour des périphériques spécialisés (salles de réunion) ou en Chine (services Google bloqués → Android Enterprise inutilisable). Basé sur OMA-DM, agent = portail d'entreprise Intune.

Android Enterprise Standard actuel

Depuis Android 5.0 (2014). Repose sur les services mobiles Google (GMS). Deux concepts : Work Profile (conteneur professionnel isolé, API Google EMM) et Device Owner (gestion complète de l'appareil, API Google Android Management). Quatre scénarios détaillés ci-dessous.

AOSP Sans services Google

Android Open Source Project : appareils sans GMS, typiquement des casques VR/AR professionnels. Inscription sans compte utilisateur associé, via l'infrastructure IME/Sidecar — le portail d'entreprise fait office d'agent MDM. Périphériques configurés en mode appareil partagé (Device Shared Mode) Entra ID, avec SSO entre utilisateurs.

Android Enterprise : les quatre scénarios

Work Profile BYOD

Appareil personnel avec un profil professionnel. Partition séparée : applications et données pro isolées du reste. Contrôle granulaire des ressources pro, vie privée respectée côté perso.

Dedicated / COSU Company Owned, Single Use

Appareils à usage unique — kiosques, points de vente. Microsoft recommande la surcouche Managed Home Screen, personnalisable, pour le mode kiosque et les appareils partagés.

Fully Managed / COBO Company Owned, Business Only

Appareil d'entreprise entièrement géré dès l'inscription : contrôle total des configurations, applications et politiques de sécurité.

COPE Company Owned, Personally Enabled

Combine appareil entièrement géré et flexibilité du Work Profile : partitions distinctes pro/perso sur un appareil qui appartient à l'entreprise.

AOSP : ce qui est géré et ce qui ne l'est pas

Pas de déploiement d'applications depuis le Google Play Store (pas de GMS), pas de stratégies de protection applicative liées au store. En revanche : stratégies de restriction, certificats (SCEP, PKCS), certificats de confiance, profils Wi-Fi, stratégies de conformité, applications métier dont les sources sont disponibles. Constructeurs supportés à l'écriture du livre : HTC, Meta, PICO, Realwear, Lenovo, DigiLens Inc, Vuzix, Zebra.

5.Grille de lecture transverse

Le même dégradé « BYOD léger → conteneur isolé → contrôle total d'entreprise » traverse les trois plateformes :

BYOD légerEnregistrement manuel dans Intune uniquementDevice EnrollmentDevice Administrator (legacy)

Retenir en une phrase : Intune gère soit l'appareil (MDM) soit uniquement l'application (MAM) ; et sur chaque plateforme, ce même dégradé BYOD → conteneur isolé → contrôle total revient, avec pour Windows une dimension historique supplémentaire (traditionnel → cogestion → moderne).
