Labo Intune — Sécurité et conformité

Mise en pratique du fil conducteur « Protéger → Vérifier → Contrôler » sur un tenant réel

Scénario : vous équipez un groupe pilote « Marketing » du triptyque complet — une stratégie qui protège les postes, une stratégie qui vérifie leur état, et une règle d'accès conditionnel qui exploite ce résultat. Chaque exercice reprend un étage précis de la fiche de cours, dans l'ordre où elle les présente.

Prérequis à vérifier avant de commencer Licence Intune Plan 1 sur votre compte admin. L'exercice 4 (accès conditionnel) nécessite Entra ID P1 ou supérieur — si vous ne l'avez pas, traitez-le en observation. Un appareil Windows géré est utile pour observer l'effet des exercices 1 et 2, mais pas indispensable pour les créer. Tenant utilisé : NextstepPRO.onmicrosoft.com (ou votre tenant de pratique).
Cours § 5 — Étage Protéger : ordinateurs et serveurs

Exercice 1 — Créer une stratégie Antivirus Protéger

But : matérialiser l'étage « Protéger » avec la brique la plus réactive du chapitre — l'antivirus.
  1. Endpoint Security → Antivirus → Create policyPlateforme : Windows 10, 10.1, and later. Profil : Microsoft Defender Antivirus.
  2. Configurer les paramètres clésActivez la protection en temps réel (Real-time protection), la protection cloud (Cloud protection) et les analyses planifiées quotidiennes.
  3. Nommer et assignerNom : AV-Windows-Marketing. Assignez à un groupe de test contenant un ou plusieurs postes Windows.
Résultat attenduLa stratégie apparaît dans Endpoint Security → Antivirus avec un statut de déploiement. Sur un appareil cible déjà synchronisé, la protection en temps réel doit apparaître active dans Sécurité Windows.
Cours § 7 — Étage Vérifier : conformité des appareils

Exercice 2 — Créer une stratégie de conformité Windows Vérifier

But : construire le référentiel qui définit « conforme » pour votre organisation — l'étage Vérifier ne fonctionne que s'il existe une stratégie à évaluer.
  1. Devices → Compliance → Policies → Create policyPlateforme : Windows 10 and later.
  2. Device HealthActivez le chiffrement (BitLocker) requis.
  3. System SecurityExigez un mot de passe, une longueur minimale de 6 caractères, et le firewall actif.
  4. Actions for noncomplianceAjoutez une action « Send email to end user » à 0 jour, et « Mark device noncompliant » à 3 jours de grâce.
  5. Nommer et assignerNom : COMP-Windows-Marketing. Assignez au même groupe de test.
Résultat attenduLa stratégie apparaît dans Devices → Compliance → Policies. Sur un appareil cible, l'onglet Device compliance affiche désormais un statut (Compliant / Not compliant) au lieu de « Not evaluated ».
Cours § 7 — Étage Vérifier : scripts de conformité personnalisée

Exercice 3 — Écrire un script de conformité personnalisée Vérifier (avancé)

But : vérifier un paramètre que les stratégies de conformité standard ne couvrent pas — exactement le cas d'usage du chapitre.
  1. Préparer le script de découverteCréez un fichier PowerShell qui renvoie un JSON, par exemple la version du BIOS de la machine.
  2. Préparer le fichier de règles JSONUn second fichier qui définit l'opérateur de comparaison attendu (voir extraits ci-dessous, repris du cours).
  3. Endpoint Security → Device Compliance → Scripts → AddImportez le script PowerShell.
  4. Créer une stratégie de conformité personnaliséeDevices → Compliance → Policies → Create policy → Compliance settings → Custom compliance → sélectionnez le script importé et le fichier JSON associé.
$hash = @{ Manufacturer = $WMI_ComputerSystem.Manufacturer; BiosVersion = $WMI_BIOS.SMBIOSBIOSVersion } return $hash | ConvertTo-Json -Compress
{ "SettingName":"BiosVersion", "Operator":"GreaterEquals", "DataType":"Version", "Operand":"2.3" }
Résultat attenduLa stratégie personnalisée apparaît dans Devices → Compliance → Policies, avec le script associé visible dans son résumé — vous savez désormais construire une règle que Microsoft ne propose pas nativement.

Rappel du cours : limite de 100 Ko et 100 règles par fichier JSON.

Cours § 8 — Étage Contrôler : accès conditionnel

Exercice 4 — Bloquer l'accès aux appareils non conformes Contrôler

But : fermer la boucle du triptyque en exploitant le résultat de l'étage Vérifier comme condition d'accès aux ressources — Zero Trust en pratique.
  1. Entra ID admin center → Protection → Conditional Access → Create new policyNom : CA-Compliant-Only-Marketing.
  2. UsersCiblez votre groupe de test uniquement (jamais « All users » en premier test).
  3. Target resourcesSélectionnez une application cloud, par exemple Office 365 Exchange Online.
  4. GrantGrant access → cochez « Require device to be marked as compliant ».
  5. Enable policyLaissez en Report-only pour un premier test sans risque de blocage réel, puis basculez en On une fois validé.
Résultat attenduLa politique apparaît dans Conditional Access → Policies. En mode Report-only, Entra ID → Sign-in logs montre les évaluations sans bloquer réellement les connexions — c'est la façon sûre de tester avant activation.
