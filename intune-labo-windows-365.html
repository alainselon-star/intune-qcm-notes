Labo Intune — Windows 365

Mise en pratique du chapitre « Windows 365 » sur un tenant réel

Scénario : vous provisionnez un premier Cloud PC pilote pour un utilisateur test, en suivant exactement le point de convergence du chapitre — la stratégie de provisionnement. Si votre tenant ne dispose d'aucune licence Windows 365, traitez tous les exercices en observation : le but est de savoir où se trouve chaque réglage et ce qu'il détermine, pas nécessairement de faire naître un Cloud PC réel.

Prérequis à vérifier avant de commencer Une licence Windows 365 (Business ou Enterprise) assignée à au moins un compte de test est nécessaire pour aller jusqu'au bout des exercices 2 à 5. Sans elle, vous pouvez tout de même explorer les menus et comprendre chaque réglage. Tenant utilisé : NextstepPRO.onmicrosoft.com (ou votre tenant de pratique).
Cours § 2 — Deux familles de licence

Exercice 1 — Identifier les licences Windows 365 disponibles Lecture

But : savoir, pour votre propre tenant, quelle famille de licence est disponible avant de construire une stratégie de provisionnement qui la référence.
  1. Microsoft 365 admin center → Billing → LicensesRecherchez « Windows 365 » dans la liste — notez s'il s'agit d'Enterprise, de Frontline Dedicated, ou de Frontline Shared.
  2. Assigner une licence à un compte de testSi vous en avez une disponible, assignez-la à un utilisateur de test (ex. test.helpdesk1 si vous avez fait le labo RBAC).
Résultat attenduVous savez dire quelle famille de licence Windows 365 votre tenant possède, et un compte de test en dispose (ou vous documentez clairement l'absence de licence pour la suite du labo).
Cours § 4 — Les images

Exercice 2 — Repérer les images disponibles Lecture

But : distinguer une image de la galerie d'une image personnalisée avant de construire la stratégie de provisionnement.
  1. Devices → Windows 365 → Device imagesConsultez la liste des images de galerie proposées par Microsoft (mises à jour mensuellement).
  2. Add → Custom imageSans forcément aller au bout : repérez que l'assistant demande une source Azure (VHD ou capture de VM) et rappelle les contraintes — Génération 2, généralisée via Sysprep, jamais jointe au préalable.
Résultat attenduVous pouvez citer au moins une image de galerie disponible dans votre tenant, et expliquer en une phrase pourquoi une image personnalisée doit être un socle neutre.
Cours § 5 — La stratégie de provisionnement

Exercice 3 — Créer une stratégie de provisionnement Provisionnement

But : construire le point de convergence du chapitre — l'endroit unique où licence, jointure, réseau et image se rencontrent.
  1. Devices → Windows 365 → Provisioning policies → Create policyNom : PROV-Cloud-PC-Pilote.
  2. Join typeMicrosoft Entra join — le plus simple pour un premier essai.
  3. NetworkMicrosoft hosted network — aucune configuration réseau préalable requise.
  4. ImageSélectionnez une image de galerie repérée à l'exercice 2 (avec Microsoft 365 Apps préinstallé).
  5. ConfigurationLangue/région, et laissez le modèle de nommage par défaut (%USERNAME:X%).
  6. AssignmentsAssignez au groupe contenant votre compte de test licencié.
Résultat attenduLa stratégie apparaît dans Provisioning policies. Si un utilisateur licencié est dans le groupe assigné, un Cloud PC commence à se provisionner automatiquement, visible dans Devices → All devices sous quelques minutes à quelques heures.
Cours § 3 — Le réseau

Exercice 4 — Comparer les deux modèles réseau Observation

But : comprendre l'arbitrage central du chapitre entre simplicité et intégration réseau, sans nécessairement construire une connexion réseau Azure complète.
  1. Devices → Windows 365 → Azure network connectionOuvrez Add → repérez les champs demandés : abonnement Azure, réseau virtuel (VNet), sous-réseau.
  2. Comparer avec le réseau hébergéRevenez à la stratégie de provisionnement de l'exercice 3 : le choix « Microsoft hosted network » ne demande aucun de ces champs.
Résultat attenduVous savez expliquer pourquoi seule la connexion réseau Azure permet l'Entra Hybrid Join et l'accès aux ressources internes, au prix d'une configuration réseau préalable.
Cours § 6 — Trois extensions matérielles

Exercice 5 — Repérer le prérequis Autopilot de Windows 365 Boot Lecture

But : vérifier le seul point de contact explicite entre ce chapitre et celui sur Windows Autopilot.
  1. Devices → Windows 365 → Device images / Windows 365 BootRepérez la mention exigeant que la machine physique soit enregistrée dans le service Windows Autopilot et ajoutée à un groupe Entra dédié.
  2. Croiser avec Windows AutopilotDevices → Enrollment → Windows Autopilot devices : si vous avez fait le labo Autopilot, retrouvez-y un appareil enregistré éligible.
Résultat attenduVous savez expliquer pourquoi un PC physique « anonyme », jamais enregistré dans Autopilot, ne peut pas démarrer directement dans son Cloud PC via Windows 365 Boot.
