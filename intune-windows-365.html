MD-102 · Provisionnement des appareils Windows

Windows 365 — le PC qui naît déjà enregistré

Un PC dans le cloud n'a pas besoin d'être « enrôlé » : il naît déjà joint à Entra ID et déjà inscrit dans Intune. Ce que la virtualisation complique, en échange, c'est tout autre chose — le réseau et le partage entre utilisateurs.

Ce n'est ni Windows Autopilot ni Microsoft 365 — les deux confusions les plus courantes. Windows 365 est un service Desktop-as-a-Service (DaaS) : Microsoft provisionne une machine virtuelle Windows complète, accessible depuis n'importe quel appareil connecté à Internet. Le point de départ pour comprendre ce chapitre : contrairement à tout ce qu'on a vu jusqu'ici, il n'y a aucun enregistrement à proprement parler — pas d'OOBE à observer, pas de hash à collecter. Le PC existe déjà « géré » au moment même où il est créé.

01 Le concept : un PC qui n'existe pas tant que personne n'y touche

Reprenons le tronc commun des fiches précédentes — identité, canal, profil. Pour un PC physique, ces trois briques se construisent pendant le déballage de la machine. Pour un Cloud PC, elles sont déjà posées avant même que la machine virtuelle existe : dès qu'un administrateur assigne une licence et une stratégie de provisionnement à un utilisateur, Azure crée la VM directement jointe (Entra ID ou Entra Hybrid) et directement inscrite dans Intune. Il n'y a jamais d'écran d'accueil à traverser pour l'IT.

Ce que la fiche Autopilot appelait le « profil de mise en service » devient ici la stratégie de provisionnement — même rôle, contexte différent. Et comme il n'y a plus de matériel physique à acheter ni de hash à gérer, la complexité se déplace ailleurs : vers la question du réseau (comment cette VM, qui vit dans un datacenter Microsoft, atteint vos ressources internes ?) et celle du partage (combien de personnes une seule licence peut-elle servir ?).

03 Le réseau : la vraie complexité de Windows 365

Un PC physique est déjà sur votre réseau d'entreprise dès qu'il y est branché. Un Cloud PC, lui, naît dans un datacenter Azure — encore faut-il décider comment il atteint le reste du monde. Deux options, avec un arbitrage clair entre simplicité et intégration réseau.

Le réseau hébergé par Microsoft est l'option zéro-configuration : un accès Internet fonctionnel en quelques clics, mais aucune visibilité sur vos ressources internes. La connexion réseau Azure (ANC) demande la mise en place préalable d'un réseau virtuel et d'une interconnexion (VPN site à site ou ExpressRoute) — en échange, le Cloud PC devient un citoyen à part entière de votre réseau, avec les mêmes outils de sécurité réseau (NSG, Azure Firewall) que n'importe quelle VM Azure. C'est aussi la seule option qui permette l'Entra Hybrid Join, puisque le Cloud PC doit alors atteindre un contrôleur de domaine Active Directory — invisible depuis le réseau hébergé par Microsoft.

La contrainte « jamais jointe à Active Directory, Entra ID, Intune ou Configuration Manager au préalable » n'est pas anodine : une image personnalisée doit être un socle neutre, sans trace d'une identité antérieure — exactement le même principe que la généralisation Sysprep utilisée depuis des années en déploiement de systèmes d'exploitation classique, transposé à l'univers cloud.

05 La stratégie de provisionnement : où tout s'assemble

C'est le point de convergence de toutes les briques précédentes. Une stratégie de provisionnement définit, pour un groupe d'utilisateurs donné : le type de licence (Enterprise ou Frontline Dedicated/Shared), le type de jointure (Entra Join ou Entra Hybrid Join), le réseau (hébergé Microsoft ou connexion Azure), l'activation du SSO, l'image à utiliser, la langue/région, un éventuel modèle de nommage (%USERNAME:X%, %RAND:X%), et l'usage optionnel de Windows Autopatch pour la gestion des mises à jour — sauf pour le mode Frontline partagé, où l'absence de propriétaire unique rend la notion de cycle de mise à jour personnel peu pertinente.

Le pont avec la fiche Autopilot

Windows 365 Boot est le seul endroit où les deux mondes de ce mini-parcours se rencontrent explicitement : la machine physique doit être enregistrée dans le service Windows Autopilot — exactement le mécanisme détaillé dans la fiche précédente — avant de pouvoir démarrer directement dans un Cloud PC. Un PC physique « anonyme » ne peut pas utiliser cette fonctionnalité.

07 Mémo de synthèse

Ce n'est ni Autopilot ni M365

Windows 365 = un PC virtuel dans le cloud (DaaS). Aucun enregistrement à observer : il naît déjà géré.

Enterprise vs Frontline

Enterprise = un utilisateur, un Cloud PC. Frontline = rotation entre plusieurs Cloud PC ou plusieurs utilisateurs, jamais de concurrence.

Le vrai arbitrage : le réseau

Hébergé Microsoft = simple, Internet seulement. Connexion Azure (ANC) = intégré à votre réseau, obligatoire pour l'Entra Hybrid Join.

Boot exige Autopilot

Seule fonctionnalité Windows 365 qui redemande un enregistrement Autopilot classique — sur la machine physique, pas sur le Cloud PC.

À retenir avant tout le reste

Windows 365 déplace la question de « comment enregistrer cet appareil » vers « où faire vivre cet appareil ». La jointure et l'inscription Intune sont automatiques et non négociables ; ce qui reste à décider, c'est uniquement le réseau que le Cloud PC pourra voir, l'image dont il héritera, et combien de personnes se partageront la licence qui le finance.
